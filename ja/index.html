作ったきっかけ

警告メールを見落として、Jiraのサイトが消えました

記事を読んだ方は、失効ルールの表へ。

6月から、個人開発の作業管理にJiraの無料サイトを使っていました。チケットは100件を超えていて、AIがAPI経由でほぼ毎日書き込んでいたサイトです。それでも非アクティブと判定されて、サイトごと消えました。

  1. 8月28日「9月11日に無効化されます」とメールが届く
  2. 9月5日「まもなく無効化されます」とメールが届く
  3. 9月12日無効化
  4. 9月20日404になっているのに気づき、サポートに問い合わせ
  5. 9月24日サポートが「復旧不可」と回答

警告メールは2回来ていて、1通目には日付も書いてありました。毎週届くJiraのお知らせメールと一緒に、読まずにアーカイブへ入れていたんです。

Atlassianがアクティビティの例に挙げているのは、ダッシュボードを開くといったブラウザでの操作です。API経由の書き込みは数えられていなかったようです。公式に「APIは数えない」と書いてあるわけではないので、ここは推測です。

ほかの無料枠も調べてみると、止まる条件はサービスごとにバラバラでした。覚えておくのは無理だと思ったので、Keepaliveを作り始めました。

止まる条件

個人開発でよく使う無料枠の、失効ルール

各社の公式ドキュメントで確認した内容です（2026年10月時点）。Jiraのデータ削除だけは公式の記載ではなく、私の場合に起きたことです。

サービス条件何が起きるか出典
Jira / Confluence Free 非アクティブ。日数は公式ドキュメントに記載なし サイトの無効化（私の場合は、その後データも削除され、復旧できませんでした） Atlassian
Supabase Free 非アクティブ1週間 プロジェクトの一時停止（停止から1年以内なら復元可） Supabase
Render Free Postgres 作成から30日。使っていても失効 DBが失効し、14日の猶予後に削除 Render
MongoDB Atlas Free 非アクティブ30日 クラスターの一時停止 MongoDB
GitHub Actionsのcron リポジトリの活動なし60日 スケジュール実行の無効化（publicリポジトリ） GitHub

最後の行について。Supabaseを止めないためのpingをGitHub Actionsのcronで回している場合、publicリポジトリに60日間コミットなどの動きがないと、そのcron自体が止まります。

これを全部覚えておく代わりに、Keepaliveが期限を数えて知らせます。ウェイトリストに登録

使い方（開発中）

使い方のイメージ（予定）

01

サービスを登録する

一覧から選ぶか、登録完了メールや警告メールを自分専用のKeepaliveアドレスに転送するだけです。失効ルールはKeepaliveが調べて持っています。日数が公開されていないサービスは、届いた警告メールをもとに知らせます。

02

期限を数える

非アクティブで止まるものは、登録した日か、最後に「確認した」を押した日から数えます。作成日から決まるものは作成日から。各サービスのパスワードやAPIキーは、預けなくていい形で作っています。

03

期限の前に知らせる

対処できる日数を残して、メールが届きます。対応したら「確認した」を押すと、次の期限を数え直します。

よくある質問

カレンダーに入れておけば十分では？

サービスが1つなら、それで十分です。ただ、カレンダーに入れるには、サービスごとのルールを自分で調べて覚えておく必要があります。日数が公式ドキュメントに書かれていないサービスもあります。その手間をなくすのがKeepaliveです。

メールを見逃したのに、またメール？

Jiraの警告メールは、毎週のお知らせメールと同じ差出人・同じ見た目で届いて、その中に埋もれました。Keepaliveが送るのは、期限が近づいたときのメールだけにする予定です。定期的なお知らせメールは送りません。

cronでpingすれば済むのでは？

Supabaseなら、多くの場合それで防げます。ただ、私のJiraはAPIでほぼ毎日使っていても止まりました。使っていても30日で失効するRenderの無料DBにも、pingは効きません。そのcron自体も、publicリポジトリに動きがなければ60日で止まります。

なお、Keepaliveには自動でpingして非アクティブ判定をすり抜ける機能は付けません。知らせるだけです。
