Jiraは、使われていない無料サイトを無効化することがあります。Supabaseは1週間動きがないと一時停止し、Renderの無料DBは使っていても作成から30日で失効します。止まる条件はサービスごとに違います。Keepaliveは、その期限を代わりに数えて知らせるツールです。いま開発中です。

早期アクセス（正式公開前に先に使える期間）を始めるときに、メールを1通送ります。アドレスは、その案内とお問い合わせへの返信にだけ使います（プライバシー）。

何があったか

Jiraの無料サイトが、まるごと消えました

記事で読んだ方は、失効ルールの表へ。

個人開発の作業管理に、Jiraの無料サイトを使っていました。6月から使い始めて、チケットは100件を超えていました。企画も、何をなぜ決めたかの記録も、全部そこに入れていました。

9月20日に気づいたときには、404になっていました。権限エラーではなく、サイトごとなくなっていました。サポートに問い合わせると、データはすでに削除されていて復旧できない、という回答でした。

このJiraは、AIからAPI経由でほぼ毎日更新していました。ただ、Atlassianのドキュメントがアクティビティの例に挙げているのは、ダッシュボードを開く、作業項目を表示する、といったブラウザでの操作です。API経由の操作は数えられていなかったようです。公式に「APIは数えない」と書いてあるわけではないので、ここは推測です。

  1. 8月28日「9月11日に無効化されます」とメールが届く
  2. 9月5日「まもなく無効化されます」とメールが届く
  3. 9月12日無効化
  4. 9月24日サポートが「復旧不可」と回答

警告メールは2回届いていて、1通目には日付も書いてありました。Jiraからは毎週お知らせメールが来ていて、私はいつも読まずに既読フォルダへ入れていました。警告メールも同じように流してしまいました。

そのあと、自分が使っているほかの無料枠の失効条件を公式ドキュメントで調べてみると、ルールはサービスごとにバラバラでした。それで、各社の期限を数えて知らせ、警告メールも1か所に集めるツールを作り始めました。

止まる条件

個人開発でよく使う無料枠の、失効ルール

各社の公式ドキュメントで確認した内容です（2026年10月時点）。ただしJiraのデータ削除は、公式の記載ではなく私の場合の出来事です。

サービス条件何が起きるか出典
Jira / Confluence Free 非アクティブ。日数は公式ドキュメントに記載なし サイトの無効化（私の場合は、その後データも削除され、復旧できませんでした） Atlassian
Supabase Free 非アクティブ1週間 プロジェクトの一時停止（停止から1年以内なら復元可） Supabase
Render Free Postgres 作成から30日。使っていても失効 DBが失効し、14日の猶予後に削除 Render
MongoDB Atlas Free 非アクティブ30日 クラスターの一時停止 MongoDB
GitHub Actionsのcron リポジトリの活動なし60日 スケジュール実行の無効化（publicリポジトリ） GitHub

最後の行だけ補足します。Supabaseを止めないためのpingをGitHub Actionsのcronで回している場合、publicリポジトリに60日間コミットなどの動きがないと、そのcron自体が止まります。

期限を代わりに数えて知らせるツールを作っています。ウェイトリストに登録

使い方（開発中）

使い方のイメージ（予定）

01

サービスを登録する

一覧から選ぶか、そのサービスの登録完了メールや警告メールを、自分専用のKeepaliveアドレスに転送します。各サービスの失効ルールはKeepaliveが調べて持っておきます。日数が公開されていないサービスは、届いた警告メールをもとに知らせます。

02

期限を数える

プロジェクトごとに期限を追います。非アクティブで止まるものは、登録した日か最後に「確認した」を押した日から、固定期限のものは作成日から数えます。各サービスのパスワードやAPIキーを預けなくていい形で作っています。

03

期限の前に知らせる

対処できる余裕をもって、メールが届きます。対応したら「確認した」を押すと、そこから次の期限を数え直します。

よくある疑問

「メールを見逃したのに、またメール？」

Jiraの警告メールは、毎週来るお知らせメールと同じ差出人・同じ見た目で届き、その中に埋もれました。Keepaliveのメールは、期限が近づいたときに送る予定です。定期のお知らせメールを送る予定はありません。

「cronでpingすれば済むのでは？」

Supabaseなら、多くの場合それで防げます。ただし、Jiraは私の場合、API経由でほぼ毎日使っていても止められました。使っていても期限が来るRenderの無料DBにも、pingは効きません。そのcronも、publicリポジトリに動きがなければ60日で止まります。

カレンダーのリマインダーも、サービスが1つなら十分です。無料枠が増えると、ルールがそれぞれ違い、日数が公式ドキュメントに書かれていないものもあります。Keepaliveは、サービスごとの期限を数えて、その前にメールで知らせます。自動でpingして非アクティブ判定をすり抜ける機能は付けません。知らせるだけです。

アドレスは、早期アクセスの案内と、お問い合わせへの返信にだけ使います。削除したいときはご連絡ください。

プライバシーについて：フォームに入力したメールアドレスは、米国のフォーム送信サービスFormspree（Formspree, Inc.）を経由して運営者に届き、同社のサーバーにも保存されます。使い道は、Keepaliveの早期アクセスの案内と、お問い合わせへの返信だけです。どのページ・どの投稿から来たか（参照元とURLのutmパラメータ）も一緒に記録し、投稿ごとの登録数を数えるためだけに使います。登録情報の開示・訂正・削除や利用停止のご依頼、お問い合わせは studio.nock.system@gmail.com までご連絡ください。安全管理の方法や、データの保存先の国の制度については、お問い合わせいただければお答えします。
