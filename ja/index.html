Jiraは使われていないサイトを無効化します。Supabaseは1週間動きがないと一時停止し、Renderの無料DBは使っていても作成から30日で失効します。止まる条件はサービスごとに違います。Keepaliveは、その期限が来る前にメールで知らせます。

公開したときにメールを1通送ります。アドレスはそれ以外に使いません。

何があったか

Jiraの無料サイトが、まるごと消えました

個人開発の作業管理に、Jiraの無料サイトを使っていました。6月から使い始めて、チケットは100件を超えていました。企画も、何をなぜ決めたかの記録も、全部そこに入れていました。

9月20日に開こうとしたら、こうなっていました。

$ curl -I https://my-site.atlassian.net HTTP/2 404

権限エラーではなく、サイトごとなくなっていました。サポートに問い合わせると、返ってきたのは「データは削除済みで、復旧はできない」という回答です。

このJiraは、AIからAPI経由でほぼ毎日更新していました。ただ、Atlassianのドキュメントがアクティビティの例に挙げているのは、ダッシュボードを開く、作業項目を表示する、といったブラウザでの操作です。API経由の操作は数えられていなかったようです。公式に「APIは数えない」と書いてあるわけではないので、ここは推測です。

  1. 8月28日「9月11日に無効化されます」というメール
  2. 9月5日「まもなく無効化されます」というメール
  3. 9月12日無効化
  4. 9月24日サポートから「復旧不可」の回答

警告メールは2回届いていて、日付も書いてありました。Jiraからは毎週お知らせメールが来ていて、私はいつも読まずに既読フォルダへ入れていました。警告メールも同じように流してしまいました。

サイトは作り直しました。そのあと、自分が頼っているほかの無料枠も調べてみると、止まる条件も知らせ方もサービスごとに違っていました。それで、全部の期限を1か所で把握して、警告を見落としにくい形で届ける仕組みを作り始めました。

止まる条件

個人開発でよく使う無料枠の、失効ルール

各社の公式ドキュメントで確認した内容です（2026年10月時点）。ルールは予告なく変わることもあり、それも見落としやすい理由のひとつです。

サービス何が起きるか条件出典
Jira / Confluence Free サイトが無効化され、その後データ削除 非アクティブ。日数は公開されていない Atlassian
Supabase Free プロジェクトの一時停止（90日以内なら復元可） 非アクティブ1週間 Supabase
Render Free Postgres DBが失効し、14日の猶予後に削除 作成から30日。使っていても失効 Render
MongoDB Atlas Free クラスタの一時停止 非アクティブ30日 MongoDB
GitHub Actions の cron スケジュール実行の無効化（publicリポジトリ） リポジトリの活動なし60日 GitHub

最後の行は見落としがちです。Supabaseを止めないためのpingをGitHub Actionsのcronで回している場合、publicリポジトリだとそのcron自体が60日で止まります。

使い方（開発中）

登録は最初の一度だけ

01

サービスを登録する

一覧から選ぶか、そのサービスの登録完了メールや警告メールを、自分専用のKeepaliveアドレスに転送します。各サービスの失効ルールはこちらで持っているので、自分で調べる必要はありません。

02

期限を数える

プロジェクトごとに期限を追います。非アクティブで止まるものは最後に使った日から、固定期限のものは作成日から数えます。

03

期限の前に知らせる

ログインして対処できる余裕をもって、メールが届きます。「確認した」を押すと、カウントがリセットされます。

よくある疑問

「cronでpingすれば済むのでは？」

Supabaseなら、多くの場合それで防げます。ただ、ブラウザでのログインが必要なJiraや、使っていても期限が来るRenderの無料DBには効きません。そのcronも、publicリポジトリなら60日で止まります。

カレンダーのリマインダーも、サービスが1つなら十分です。ただ無料枠をいくつも使っていると、ルールがそれぞれ違い、日数が公開されていないものもあります。Keepaliveは、それをまとめて見ておく場所です。自動でアクセスして非アクティブ判定をすり抜けるような機能は付けません。知らせるだけで、どうするかは自分で決められます。

消える前に気づけるように

ウェイトリストに登録すると、早期アクセスを始めるときにメールを1通お送りします。

プライバシーについて: フォームに入力したメールアドレスは、フォーム送信サービスのFormspreeを経由して運営者に届きます。使い道はKeepaliveのローンチ通知と、それに関する連絡だけです。どのページから来たか（参照元とURLのutmパラメータ）も一緒に記録します。アドレスの削除を希望する場合は studio.nock.system@gmail.com までご連絡ください。
